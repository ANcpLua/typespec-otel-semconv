# typespec-otel-semconv — Agent Notes

You're an AI coding agent (Claude Code, Codex, aider, Gemini CLI, …) working on the `@ancplua/typespec-otel-semconv` repo.

This repo's only job is to project the upstream OpenTelemetry semantic-conventions YAML model into a single TypeSpec file (`lib/otel-keys.gen.tsp`) via Weaver. Everything in this repo serves byte-reproducibility of that one artifact.

## Architecture in one screen

```
.tools/semconv-upstream/              git submodule, pinned at v1.41.0 (e018fe6f)
templates/registry/typespec/          Weaver config + Jinja template
scripts/bootstrap-weaver.{sh,ps1}     download pinned Weaver v0.23.0
scripts/run-weaver.sh                 generate lib/otel-keys.gen.tsp (single-pass)
test/staging-dir-guard.test.sh        regression for the SEMCONV_STAGING_DIR safety guard
test/regen.test.ts                    vitest: byte-identity + git-clean
test/smoke.tsp                        `tsp compile --no-emit` smoke gate
build/_build.csproj + Build.cs        Nuke build, implements IUpstreamConventions
build.sh / build.cmd                  standard Nuke bootstrap
```

## Conventions

- **One artifact rule.** This repo emits `lib/otel-keys.gen.tsp` and nothing else. The 228-file shape (the old pure-JS implementation that previously lived here) is gone deliberately — the only sanctioned surface is the single-file Weaver projection consumed by downstream `@o-ancpplua/qyl-api-schema`.
- **Byte-identity is the contract.** `npm run verify-clean` and the regen vitest must both go green on every commit. If a change to the template or scripts produces a different byte sequence, the bump goes to `package.json#version` as `{semconv}-{n+1}` and CI re-verifies against the new committed `lib/otel-keys.gen.tsp`.
- **Bash↔PowerShell parity.** `bootstrap-weaver.sh` and `bootstrap-weaver.ps1` must stay in lockstep. Any change to one needs an equivalent change to the other. `./build.sh VerifyOtelKeysScriptParity` exercises both when `pwsh` is on PATH.
- **No manual edits to generated code.** `lib/otel-keys.gen.tsp` carries a `<auto-generated/>` header. Editing it by hand is a CI failure (`verify-clean` will catch it).
- **Pin everything.** Semconv version (`v1.41.0`), Weaver version (`v0.23.0`), and the submodule commit (`e018fe6f`) are pinned in `package.json#metadata`, `templates/registry/typespec/weaver.yaml`, and `bootstrap-weaver.{sh,ps1}` respectively. When bumping the upstream pin, all four must move together.
- **No qyl-specific anything.** This repo was extracted from `qyl/eng/semconv` deliberately to drop the qyl-flavored passes (qyl model, C# SDK constants, MD docs, SQL columns). If a future template needs to live here it must be registry-agnostic.

## Nuke component

The build implements `IUpstreamConventions` from `ANcpLua.OpenTelemetry.Conventions.Nuke` (published to nuget.org from O-ANcppLua/ANcpLua.OpenTelemetry.Conventions.Nuke). The interface ships declaration-only stubs; concrete bodies live in `build/Build.cs` and overwhelmingly shell out to the same `scripts/*.sh` callers can run by hand. Don't put logic in Build.cs that can't also be reproduced from the command line — the scripts are the canonical pipeline.

## Source-of-truth boundary

If a maintainer asks "where does X come from?", the answer is one of:

1. Upstream YAML at `.tools/semconv-upstream/model/**/*.{yaml,yml}` — authoritative for attribute names, briefs, stability, deprecation.
2. `templates/registry/typespec/{weaver.yaml,otel-keys.gen.tsp.j2}` — authoritative for shape, namespace, include set, identifier rule.
3. `scripts/*.sh` — authoritative for runtime (Weaver version, platform mapping, staging dir, install permissions).

If none of those answer the question, the change probably doesn't belong in this repo.
